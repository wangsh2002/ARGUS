# 03 — 实现多候选不完整线索匹配

**What to build:** 让分析人员用不完整行为或 Context 线索查询历史 AttackFlow，以规范 FlowMatchResult 获得多个可解释候选，并在现有候选与详情页面查看输入命中、路径补全和后续预测。

**Blocked by:** 02 — 迁移全部历史攻击流

**Status:** completed

- [x] 一次查询可以使用行为文本、IOC、工具、恶意软件、漏洞和可选 ATT&CK 输入匹配 Action。
- [x] 系统返回所有达到阈值的候选并使用确定性规则排序；没有足够匹配时返回无候选而不是强选一条 Flow。
- [x] 每个候选保留原始输入、目标 Action、行为或 Context 等命中类型、命中值、置信度和未解释输入。
- [x] ATT&CK-only 命中的影响低于具体行为或 Context 命中，且不能单独造成高置信候选。
- [x] 最远的 mainline 命中定义进度点；其前未命中 Action 显示路径补全，其后未命中 Action 显示后续预测。
- [x] Context 命中显示为“输入命中”，但匹配说明不会声称 Action 行为已被直接观测。
- [x] 直接命中的非 mainline Action 可以高亮，其他分支保持参考状态而不会被全部预测。
- [x] 研判运行冻结规范化输入、完整候选、算法版本和知识快照，并可以按身份重放。
- [x] 候选卡片显示命中、未解释线索、进度和得分，详情页显示三类状态及每个命中的原因。
- [x] 测试覆盖五步 Flow 命中三步、起点/中段/终点、多个候选、Context 命中、无匹配和确定性并列排序。
