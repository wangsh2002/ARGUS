# ARGUS CTI 前端重构产品规格

版本：2.0
日期：2026-07-26
状态：产品方向已确认，进入实现

> 2026-07-26 状态说明：现有攻击链工作台实现已从产品界面移除，等待下一轮重新设计。本文中的攻击链章节暂作为历史需求参考，不代表当前可用功能。

## 1. 产品定位

ARGUS 是以查询为中心、以攻击链检索为核心差异化能力的威胁情报产品。

它不试图复制微步在线的完整业务范围，也不把自己包装成安全编排或处置平台。产品重点是：

1. 查询 IOC、报告、攻击组织及其关联情报；
2. 根据多条线索匹配历史攻击链；
3. 汇总历史报告并解释攻击过程；
4. 提供有边界、非绝对口径的核查与处置建议；
5. 使用 ARGUS GPT 辅助总结、解释和比较查询结果。

ARGUS 的核心创新是攻击链级查询。IOC 仍是基础查询对象，但攻击链把分散的 IOC、事件、恶意软件、攻击组织和历史报告组织为可理解的真实过程。

## 2. 产品边界

### 2.1 当前阶段要做

- 综合情报查询；
- IOC 与其他情报实体详情；
- 攻击链匹配输入；
- 最佳匹配与候选攻击链比较；
- 只读攻击链结果；
- 历史报告检索与详情；
- 情报关系图谱；
- 独立 ARGUS GPT 页面；
- 本地查询历史；
- 真实、可点击的报告来源。

### 2.2 当前阶段不做

- 编辑、添加、删除或重排查询结果中的攻击链节点；
- 修改节点名称、类型和关系；
- 证据状态标记、人工核验工作流和分析备注；
- 调查案件协作、任务流转和多人协同；
- 自动封禁、隔离、删除或配置修改；
- 资产测绘、漏洞数据库、文件沙箱和漏洞利用生成；
- API 套餐、奖励计划、社区评论和用户标签；
- 数据库无法支持的 Whois、PDNS、证书、全球覆盖率等信息；
- 绝对归因或绝对处置结论。

节点编排只是一种可视化查询输入方式，不是攻击链编辑器。

## 3. 设计原则

### 3.1 查询优先

- 首页第一视觉位是统一查询框；
- 首页直接提供“综合情报查询、攻击链匹配、ARGUS GPT”三种查询模式；
- 搜索前不在页头重复放置搜索框；
- 进入结果或其他子页面后，搜索框收缩到页头左侧；
- 所有页面都应提供明确的继续查询路径。

### 3.2 攻击链优先

- 攻击链结果始终出现在攻击链详情页顶部；
- 节点主标题使用真实实体或事件名称；
- ATT&CK 只补充阶段和技术定义，不替代真实节点；
- 主链优先，分支附着在相关节点下方；
- 顶部攻击链控制在一个桌面首屏内完成浏览。

### 3.3 先结论，后解释

攻击链结果的固定阅读顺序为：

1. 攻击链主线；
2. 综合结论；
3. 历史总结；
4. 处置建议；
5. 攻击链明细；
6. 归因辅助；
7. 全部来源与技术报告。

技术细节不能挤占结论和总结的首要位置。

### 3.4 真实可追溯

- 只展示已入库数据或明确标记的用户输入；
- 每个来源显示真实标题、发布机构、发布日期和可点击原文；
- 无原文链接时不伪造链接；
- 用户输入未匹配到情报时必须标明“输入线索”或“暂无直接证据”；
- 多个来源之间存在冲突时保留不确定性说明。

### 3.5 建议而非处置

- 使用“建议核查、可考虑、如环境适用”等表达；
- 建议必须说明适用条件和依据；
- 产品只提供建议，不执行处置动作；
- 归因只作为辅助判断。

## 4. 信息架构

### 4.1 顶部主导航

1. 综合查询；
2. 攻击链；
3. 历史报告；
4. 情报图谱；
5. ARGUS GPT。

攻击组织是可查询实体和关联内容，不占据主导航。历史查询位于攻击链或搜索入口内部，不作为独立产品模块。

### 4.2 页面地图

- 综合查询首页；
- IOC / 实体详情；
- 攻击链查询输入；
- 攻击链候选结果；
- 攻击链详情；
- 历史报告列表；
- 历史报告详情；
- 情报图谱；
- ARGUS GPT。

## 5. 全局布局与视觉语言

### 5.1 页面状态

首页：

- 顶部仅展示品牌、主导航和用户状态；
- 页面中央展示品牌说明与主搜索；
- 主搜索点击后在原位置展开模式、示例和历史查询。

子页面：

- 搜索框收缩到页头品牌右侧；
- 页头保持 64px 左右的紧凑高度；
- 主导航继续位于页面上方；
- 桌面端内容最大宽度约 1440px。

### 5.2 视觉规范

- 使用白色内容面和极浅灰蓝页面背景；
- 红色只用于风险、当前选中和关键操作；
- 正文以深灰色为主，次要信息使用中性灰；
- 页面主要依靠标题、字号、留白、细分隔线和表格组织；
- 卡片只用于真正独立的工具、侧栏、浮层或可操作对象；
- 禁止用大量边框把每段文字包装成卡片；
- 禁止大面积渐变、发光效果和仪表盘式指标卡；
- 风险标签紧凑，不使用大色块；
- 桌面优先，窄屏只需保证基本可用。

### 5.3 详情页骨架

详情页优先使用：

- 左侧约 75% 的连续主内容；
- 右侧约 25% 的独立辅助栏；
- 主内容内部用分隔线组织连续章节；
- 右侧用于图谱、当前查询上下文和继续查询入口。

## 6. 综合查询首页

### 6.1 主搜索

三种模式：

1. 综合情报查询；
2. 攻击链匹配；
3. ARGUS GPT。

综合情报查询接受 IP、域名、URL、Hash、CVE、攻击组织、恶意软件和报告关键词。

攻击链匹配切换后，搜索框在原位置展开为多行输入，并提供：

- 粘贴线索；
- 上传文件；
- 节点编排。

ARGUS GPT 模式提交后进入独立 GPT 页面。

### 6.2 首页辅助内容

只展示数据库可真实维护的内容：

- 最近收录的攻击链报告；
- 常用查询示例；
- 本地历史查询。

不展示无法验证的覆盖规模、日均新增和平台排行。

## 7. IOC 与实体详情

单个 IOC 查询不强行突出攻击链。详情采用微步式连续信息结构：

1. 情报结论与基础信息；
2. 情报洞察；
3. 相关攻击链；
4. 相关报告；
5. 关联 IOC；
6. 全部来源。

右侧始终展示：

- 精简关系图谱；
- 当前实体关联数量；
- 继续查询入口；
- 打开全屏图谱入口。

节点和关联实体可继续查询。相关攻击链与其他关联内容同级。

## 8. 攻击链查询输入

### 8.1 单一输入面

攻击链输入不能展示为多个平级功能卡片。页面只保留一个主输入面，内部切换三种模式：

1. 粘贴线索：告警、日志、IOC 列表或自然语言；
2. 上传文件：TXT、JSON、CSV 或 STIX；
3. 节点编排：使用真实节点名称和可选关系组织查询条件。

报告入口属于报告详情页，GPT 属于独立页面，模板只作为输入示例。

### 8.2 解析预览

提交前在输入面下方显示轻量预览：

- 识别出的真实节点名称；
- 输入顺序或显式关系；
- 已入库匹配与未匹配线索；
- 匹配范围说明。

解析预览不能让用户误以为输入已成为已验证情报。

## 9. 攻击链候选结果

同一组线索可能命中多个历史事件或报告。系统不得自动合并为一条确定攻击链。

候选页展示：

- 一个最佳匹配；
- 若干候选攻击链；
- 命中节点；
- 来源报告；
- 匹配强度；
- 未匹配线索；
- 时间范围。

用户选择候选后进入攻击链详情。无候选时展示可查询的已识别实体和补充输入建议，不伪造攻击链。

## 10. 攻击链详情

### 10.1 页面骨架

顶部使用“连续主线 + 固定图谱侧栏”：

- 左侧宽主内容展示攻击链、结论和后续分析；
- 右侧窄栏始终显示攻击链图谱；
- 页面首屏必须看到完整主链和图谱；
- 图谱不可折叠或隐藏到标签页中。

### 10.2 顶部攻击链

- 真实节点名称为主体；
- 节点按攻击顺序水平排列；
- 关系显示在节点之间；
- ATT&CK 阶段显示为次级标签；
- 候选分支收纳在相关主节点下方；
- 主链在桌面首屏内可浏览；
- 节点选中态清晰但不过度强调。

### 10.3 节点查询交互

节点只提供查询能力：

- 单击节点：右侧显示情报摘要、真实来源和关联线索；
- 点击节点名称或“查看详情”：进入对应 IOC、报告或组织详情；
- 不显示编辑、确认、排除、备注或状态修改操作。

### 10.4 内容顺序

攻击链之后依次完整展开：

#### 综合结论

- 风险判断；
- 最佳匹配名称；
- 匹配可信程度；
- 主要命中依据；
- 数据限制与不确定性。

#### 历史总结

- 发生了什么；
- 历史报告共同结论；
- 时间演化；
- 主要差异。

#### 处置建议

- 建议核查；
- 可考虑的遏制；
- 排查与恢复建议；
- 适用条件与依据；
- 明确“平台不执行处置”。

#### 攻击链明细

- 每个节点的阶段、类型、关系和命中来源；
- ATT&CK 补充信息；
- 未匹配线索；
- 技术证据。

#### 归因辅助

- 候选组织；
- 支持依据；
- 冲突信息；
- 不确定性。

#### 全部来源与技术报告

- 真实报告信息；
- 证据摘录；
- 发布机构与日期；
- 可点击原文。

以上章节全部展开，不使用互斥标签页或固定高度内部滚动。

## 11. 历史报告

### 11.1 报告检索

支持：

- 关键词；
- 时间；
- 来源；
- 攻击组织；
- IOC。

### 11.2 报告详情

固定顺序：

1. 报告摘要和关键结论；
2. 攻击链预览；
3. 关键 IOC；
4. 处置建议；
5. 归因辅助；
6. 原始报告信息和原文链接。

报告页可以直接发起攻击链匹配查询，但不能创建可编辑攻击链。

## 12. 情报图谱

情报图谱是独立查询页面，支持从以下对象开始：

- IOC；
- 历史报告；
- 攻击组织；
- 攻击链。

图谱能力：

- 展示真实节点名称；
- 展示关系类型和来源；
- 点击节点查看情报摘要；
- 继续关联查询；
- 跳转到实体或攻击链详情；
- 提供关系类型筛选和视图缩放。

图谱不提供增删节点、修改关系或保存画布。

## 13. ARGUS GPT

ARGUS GPT 必须独立成页，能力围绕平台情报：

- 总结历史报告；
- 解释攻击链和节点关系；
- 比较候选攻击链；
- 生成有边界的核查与处置建议；
- 回答中引用真实、可点击来源。

从 IOC、报告或攻击链页面进入 GPT 时携带当前查询上下文，但聊天界面不嵌入原页面。

模型未配置时明确显示未配置状态，不生成模拟回答。

## 14. 数据与演示边界

- 演示数据应来自公开、可访问的真实报告；
- 可以人工提取少量节点和关系作为算法尚未实现时的测试数据；
- 人工提取内容必须保留报告来源；
- 匹配算法当前允许轻量实现，重点验证页面与查询流程；
- UI 不承诺数据库尚未提供的数据；
- 所有统计只基于当前快照。

## 15. 核心验收标准

### 15.1 查询

- 首页只有一个主搜索入口；
- 首页可直接切换综合查询、攻击链匹配和 GPT；
- 子页面搜索栏收缩到页头；
- 首页辅助信息仅包含真实报告、示例和本地查询历史。

### 15.2 攻击链

- 查询结果先展示最佳匹配和候选；
- 攻击链始终位于详情页顶部；
- 首屏可以看到完整主链和始终可见的图谱；
- 节点使用真实名称；
- ATT&CK 只是补充；
- 节点只能查询，不能修改；
- 综合结论、历史总结、处置建议、攻击链明细、归因辅助和全部来源依次展开。

### 15.3 视觉

- 不使用常驻左侧导航；
- 不用大量卡片包围正文；
- 主内容以连续信息面、分隔线和表格组织；
- 红色只用于风险、当前状态和关键操作；
- IOC 详情使用宽主内容与窄图谱侧栏；
- 桌面端信息密度接近成熟威胁情报产品。

### 15.4 边界

- 没有节点编辑、证据标记、备注和处置执行；
- 没有虚构来源和虚构统计；
- 归因与处置建议均保留不确定性口径；
- Graph 和 GPT 均是查询能力，不改写情报事实。
