# ARGUS CTI 前端重构产品规格

版本：1.0  
日期：2026-07-25  
状态：已确认，进入实现

## 1. 产品定位

ARGUS 是以查询为入口、以攻击链为核心组织方式的威胁情报研判工作台。

产品不以“覆盖最多 IOC 字段”为差异化目标，而是帮助用户把零散情报、日志、报告和人工判断组织成可追溯的攻击链，并进一步完成：

1. 历史报告综合总结；
2. 参考性处置建议；
3. 调查案件沉淀与报告导出；
4. 辅助归因分析；
5. GPT 辅助查询与链路草稿生成。

## 2. 设计原则

### 2.1 查询优先

- 首页以居中大搜索框作为唯一主视觉，不在页头重复放置搜索框。
- 进入情报详情、攻击链、报告、组织或 GPT 等子界面后，搜索框收缩到页头左侧，保留连续查询能力。
- 查询模式显式区分：情报查询、攻击链、Graph、GPT。
- 系统可以提示输入类型，但用户可以主动切换模式。

### 2.2 真实可追溯

- 只展示现有数据或明确标记的用户输入。
- 每个节点、关系、总结结论均应能追溯至报告、摘录或人工操作。
- 不为缺失数据制造 Whois、PDNS、证书、沙箱结果等空壳或模拟内容。
- 没有数据的模块默认隐藏；必要时显示“当前情报源未收录”。

### 2.3 攻击链优先于 ATT&CK

- 攻击链以事件真实时序和真实节点名称为主。
- ATT&CK 仅作为阶段和技术标签补充，不替代真实攻击过程。
- IOC 是攻击链中的证据节点，但单个 IOC 查询仍采用通用情报详情结构。

### 2.4 建议而非处置

- ARGUS 只提供带适用条件、依据和置信度的参考建议。
- 产品不直接执行封禁、隔离、删除、配置修改或其他响应动作。
- 避免使用绝对归因和绝对处置口径。

## 3. 目标用户与核心任务

### 3.1 目标用户

- 安全运营和应急响应人员；
- 威胁情报分析人员；
- 需要理解告警与攻击过程的普通安全用户；
- 阅读研判报告的安全负责人。

### 3.2 主任务

`查询或输入证据 → 构建攻击链 → 对齐历史报告 → 形成总结 → 给出处置建议 → 导出报告`

归因是辅助任务，不是主任务。

## 4. 信息架构

### 4.1 主要页面

1. 综合查询首页；
2. IOC 情报详情；
3. 攻击链证据接入；
4. 攻击链研判工作台；
5. 调查案件列表与案件详情；
6. 历史报告中心与证据查看器；
7. ARGUS GPT；
8. 攻击组织档案；
9. 全屏关系图谱。

### 4.2 主导航

- 桌面端主导航横向放置在页面顶部，不使用常驻左侧栏；
- 综合查询
- 攻击链
- 调查案件
- 历史报告
- 攻击组织
- ARGUS GPT

Graph 作为查询模式和上下文能力进入，不要求独立占据主导航。

## 5. 首页与查询

### 5.1 首屏

- ARGUS 品牌与一句明确价值描述；
- 居中、宽幅的统一查询框；
- 四种模式：情报查询、攻击链、Graph、GPT；
- 常用示例和当前数据规模；
- 最近调查案件与报告入口。
- 首屏页头不显示紧凑搜索框；进入子界面后才显示。

### 5.2 输入识别

前端可识别并提示以下输入类型：

- IPv4；
- 域名；
- URL；
- Hash；
- CVE；
- 自然语言；
- 使用箭头或换行组织的攻击链片段。

输入识别只影响展示和导航，不生成数据库中不存在的情报结论。

## 6. IOC 情报详情

IOC 页面与攻击链工作台使用不同的信息层级。

### 6.1 必需模块

- 实体名称、类型与风险状态；
- 描述、首次/末次发现、来源数量和置信度；
- 相关实体与关系；
- 来源证据与历史报告；
- 关联攻击链；
- 精简关系图谱；
- 可继续查询或创建调查案件的操作。

### 6.2 数据边界

页面只根据当前 Snapshot 展示模块。当前未结构化提供的 Whois、PDNS、证书、备案和沙箱行为不展示。

## 7. 攻击链证据接入

各种输入方式平级，不默认突出其中一种：

1. 粘贴日志或告警；
2. 上传 TXT、JSON、CSV 或 STIX 文件；
3. 可视化画布手工创建节点和关系；
4. 从已有 IOC、攻击组织、历史事件或报告开始；
5. 使用常见攻击场景模板；
6. 通过 GPT 生成待确认草稿。

### 7.1 解析预览

在生成攻击链前，统一进入解析预览：

- 展示识别出的节点、时间和关系；
- 标记来源：日志提取、人工创建、情报库匹配、GPT 建议；
- 用户可以确认、取消或修改候选节点；
- 未确认内容不得显示为已验证情报。

本阶段允许仅为部分输入方式实现完整解析；其余方式应呈现清晰的 Demo 或未接入状态。

## 8. 攻击链研判工作台

### 8.1 一屏布局

工作台优先在桌面一屏内完成主要研判：

- 顶部：案件标题、查询、保存状态、导出入口；
- 中部左侧：攻击链时序主视图；
- 中部右侧：常驻精简图谱和节点证据摘要；
- 底部标签：历史总结、处置建议、归因辅助、全部来源。

页面避免把所有内容纵向堆叠成长页面。

### 8.2 攻击链表达

- 默认显示证据最强的主链；
- 节点主标题使用真实名称；
- 次级信息展示关系/行为、阶段和 ATT&CK 标签；
- 候选分支附着在相关步骤并允许展开；
- 缺失步骤和反证必须明确标记；
- 节点展示时间、置信度、证据数量和确认状态；
- 选中节点时，图谱同步聚焦，证据区域同步更新。

### 8.3 编辑

攻击链是可编辑研判草稿：

- 确认或排除候选节点；
- 新增节点；
- 调整顺序；
- 编辑关系；
- 区分系统匹配和人工确认；
- 本阶段保存为浏览器本地 Demo 草稿。

### 8.4 图谱

- 图谱始终在工作台可见；
- 默认使用精简子图，突出当前节点及其直接关系；
- 支持一键全屏；
- 节点选择与时序链双向联动；
- 全屏图谱支持关系类别筛选、拖拽和节点详情。

## 9. 历史报告总结

历史总结必须按攻击链组织，而不是仅生成一段摘要：

- 多份报告的共同结论；
- 各阶段关键证据；
- 报告之间的差异与冲突；
- 时间演化；
- 每条结论的真实引用。

### 9.1 来源交互

- 点击引用先打开站内证据查看器；
- 站内查看器定位并高亮对应摘录；
- 有 `external_url` 时提供原始来源跳转；
- 无外链时只展示内部报告、来源编号和摘录，不伪造链接。

## 10. 处置建议

建议按以下类别组织：

- 立即遏制；
- 排查狩猎；
- 清除恢复；
- 长期加固。

每条建议展示：

- 优先级；
- 适用节点或阶段；
- 适用条件；
- 建议内容；
- 依据与来源；
- 置信度或不确定性说明；
- Demo 勾选状态。

建议区不提供直接执行处置的操作。

## 11. 辅助归因

- 归因显示为候选假设；
- 展示支持路径、冲突路径、贡献证据和不确定性；
- 不把归因候选作为页面主结论；
- 不使用绝对归因口径。

## 12. 调查案件

案件保存以下本地状态：

- 案件 ID、标题、创建/更新时间；
- 查询或输入来源；
- 攻击链节点与关系；
- 人工确认与排除状态；
- 备注；
- 已完成的建议项；
- 当前报告摘要。

### 12.1 本地持久化

- 使用版本化 localStorage 结构；
- 数据损坏时回退为空状态；
- 提供删除和重新打开案件的能力；
- 清楚标识“本机 Demo 草稿”。

## 13. ARGUS GPT

### 13.1 页面

- GPT 保留独立主导航页面；
- 支持对话输入和文本类附件；
- 展示当前是否连接模型；
- 提供示例安全分析问题；
- 支持携带当前案件上下文。

### 13.2 最小服务接口

供应商无关配置：

- `ARGUS_LLM_BASE_URL`
- `ARGUS_LLM_API_KEY`
- `ARGUS_LLM_MODEL`

前端请求站内 `/api/gpt`，服务端负责调用兼容 OpenAI Chat Completions 的接口。

请求：

```json
{
  "message": "分析当前证据",
  "context": {
    "case_id": "CASE-DEMO-001",
    "nodes": [],
    "sources": []
  }
}
```

响应：

```json
{
  "answer": "参考性分析文本",
  "citations": [],
  "suggested_nodes": [],
  "model": "configured-model"
}
```

### 13.3 边界

- 未配置模型时返回明确的可操作错误；
- 模型建议节点必须经用户确认后才能加入攻击链；
- 模型回答不替代来源证据；
- 本阶段不要求复杂 Agent、检索编排或高质量自动提取。

## 14. 报告导出

导出内容：

1. 管理摘要；
2. 影响与风险；
3. 攻击链；
4. 历史报告总结；
5. 处置建议；
6. 辅助归因；
7. 引用来源；
8. “仅供分析参考”声明。

首版格式：

- 浏览器打印/PDF；
- Markdown；
- 结构化 JSON。

## 15. Demo 数据策略

- 补充 3–5 篇政府机构或知名安全厂商公开报告；
- 保存真实标题、发布日期、来源和原始链接；
- 人工提取少量攻击步骤、关系和必要短摘录；
- 不完整复制受版权保护的原文；
- Demo 节点和结论必须能追溯至来源。

## 16. 视觉与响应式

- 延续 ARGUS 红、白、深灰品牌体系；
- 主工作区使用浅色，提高长文本与证据可读性；
- 全屏图谱允许使用更深的画布；
- 桌面优先，目标宽度 1440px 以上；
- 普通笔记本仍能完成主要流程；
- 移动端只保证查询、摘要和报告阅读，不要求完整图谱编辑。

## 17. 可访问性

- 所有主要操作使用真实按钮或链接；
- 输入框和图谱节点提供可访问名称；
- 键盘可切换模式、标签和节点；
- 不只依赖颜色表达状态；
- 焦点样式清晰；
- 动效遵守 `prefers-reduced-motion`。

## 18. 非目标

本阶段不实现：

- 自动处置和安全设备联动；
- 多人实时协作；
- 正式案件后端；
- 完整日志解析算法；
- 自动归因算法；
- 完整 PDF/DOCX 内容解析；
- Whois、PDNS、证书或沙箱数据采集；
- 企业级权限和审计。

## 19. 验收标准

### 19.1 查询与 IOC

- 用户可从首页切换四种查询模式；
- 查询现有 IOC 能打开真实情报详情；
- 详情只展示 Snapshot 支持的数据；
- 证据和来源可点击查看。

### 19.2 攻击链

- 用户可从示例、已有报告或手工输入进入工作台；
- 工作台在一屏内展示时序链、图谱和分析标签；
- 选择链路节点会同步图谱与证据；
- 可确认、排除、添加和调整节点；
- 改动刷新后仍保存在本机；
- 可以展开候选分支、缺口和反证。

### 19.3 核心产出

- 历史总结按阶段展示并带真实引用；
- 处置建议使用非绝对口径并带适用条件；
- 归因位于辅助标签；
- 报告可打印并下载 Markdown、JSON。

### 19.4 GPT

- 未配置 API 时页面给出明确状态；
- 配置兼容接口后能够完成一次对话；
- 回答可以显示引用和建议节点；
- 用户确认后建议节点可以加入当前案件。

### 19.5 质量

- `npm run build` 成功；
- 自动化交互测试覆盖查询、攻击链、案件保存、来源查看、导出和 GPT 未配置状态；
- 不引入虚假威胁情报；
- 不破坏现有关系图谱拖拽能力。
