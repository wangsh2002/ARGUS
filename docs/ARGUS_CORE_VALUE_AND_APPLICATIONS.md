# ARGUS 核心优势、产品亮点与应用场景

## 1. 项目概述

ARGUS 是一套面向 SOC 研判、应急响应和威胁情报运营的可追溯攻击过程研判平台。它不仅用于查找某个 IOC 或浏览一张关系图，而是将零散的告警、IOC、威胁报告和攻击行为组织为可理解、可验证、可复核的攻击路径假设。

平台围绕一个核心问题展开：**当分析人员只拿到不完整的线索时，如何快速判断其可能属于哪一类攻击过程，当前处于什么位置，还缺少哪些环节，后续应优先验证什么。**

ARGUS 因此将“攻击流”作为研判主干，将 IOC、恶意软件、工具、漏洞、资产、ATT&CK 技术、攻击组织和来源证据挂接到具体行为上，使平台同时具备过程研判、情报查询和知识沉淀能力。

## 2. 核心价值

### 2.1 从“找到一个点”升级为“理解一段过程”

传统 IOC 平台擅长回答“这个 IP、域名或样本是什么”，但往往不能直接解释它在一次攻击中承担什么作用。ARGUS 将这些情报对象挂接到“下载载荷”“建立 C2 通信”“收集浏览器数据”等原子行为上，让分析人员不仅看到“有关联”，还能看到“为什么关联、在哪一步使用”。

这一转变能够显著降低分析人员在告警平台、情报平台、报告文档和 ATT&CK 知识库之间往返比对的成本。

### 2.2 对不完整线索进行攻击流匹配

现实告警很少能覆盖一条完整攻击链。ARGUS 允许用户输入若干行为、IOC、工具、恶意软件、漏洞或 ATT&CK 线索，并在历史 AttackFlow 中返回多个候选。系统显式区分：

- **输入命中**：当前线索直接支持的行为；
- **路径补全**：位于已观测进度之前，或用于连接已命中行为的历史候选步骤；
- **后续预测**：位于当前进度之后，需要继续监测和验证的候选行为。

补全和预测不会被冒充为已发生事实。这种状态分离使系统既能提供前瞻性，又不会牺牲研判的严谨性。

### 2.3 以证据为核心，而不是只给出模型结论

ARGUS 将来源文档、证据片段、行为节点、过程关系和组织归因声明分层保存。每一个重要节点或关系都可以回到原报告中的具体片段，便于分析人员快速判断系统结论是否可信。

对安全研判系统而言，这种可追溯性不仅改善使用体验，也是内部复核、事件复盘、审计和知识继承的基础。

### 2.4 同时保留攻击主干与情报全景

ARGUS 并不把所有对象都塞进攻击链主干。主干只保留推进攻击过程的行为节点，IOC、工具、漏洞、技术和资产作为上下文依附于相关行为。这样既保证了攻击链的可读性，也避免了 IOC 在抽取和展示过程中丢失。

在全景图谱中，规范 IOC、恶意软件、工具、漏洞、攻击流、来源报告和攻击组织又可以形成统一的可展开关系网络，支持从任意对象追溯其行为上下文和来源证据。

### 2.5 将一次性报告转化为可持续复用的组织知识

大量威胁报告在阅读完成后很快就失去使用价值。ARGUS 将报告中的攻击行为、实体、别名、证据和组织归因口径沉淀到可版本化的知识库中。后续新告警或新报告到来时，过往研判结果可以直接用于候选匹配和证据对照。

这使平台的价值会随高质量情报和复核结果的积累而提升，而不是每次研判都从零开始。

## 3. 差异化亮点

| 能力 | 对业务的意义 |
|---|---|
| 不完整线索的多攻击流匹配 | 在证据不全时快速缩小调查范围，不强行选择唯一答案 |
| 命中、补全、预测三态分离 | 同时呈现已知事实、历史候选和后续风险，减少误导 |
| 攻击主干、分支与泳道投影 | 将复杂事件转化为适合 SOC 和应急人员阅读的过程视图 |
| 行为与 IOC 上下文绑定 | 看到 IOC 在哪一步被使用，而不是只得到一组无结构指标 |
| 证据级追溯 | 将“模型认为”变为“可以回到原文验证” |
| 规范实体、组织别名与来源提及分层 | 减少同一组织或 IOC 被重复建模，同时保留各家来源的原始口径 |
| 在线研判与知识入库分离 | 防止一次查询或模型猜测直接污染历史知识库 |
| 质量门、复核、版本发布与回滚 | 支持情报运营流程，降低错误数据扩散风险 |

ARGUS 的优势不在于用一个大模型代替所有专家判断，而在于把模型抽取、确定性规则、历史攻击流、证据约束和人工复核放到同一条可控流程中。这种组合比纯模型问答更稳定，也比传统静态情报库更接近实际研判任务。

## 4. 典型应用场景

### 4.1 SOC 告警二线研判

分析人员将 EDR、NDR、邮件安全或 SIEM 中的若干关键行为和 IOC 提交给 ARGUS。系统返回可能匹配的历史攻击流、已命中位置、待补查的中间环节和需要优先监测的后续行为，帮助分析人员快速形成调查思路。

### 4.2 应急响应与事件复盘

对于已经发生的入侵事件，ARGUS 可以按时序、阶段或资产泳道重建关键攻击过程，并将样本、域名、命令、漏洞和证据依附到相关步骤。该视图可用于确定影响范围、识别日志缺口、组织复盘和支撑后续检测建设。

### 4.3 威胁情报生产与知识入库

威胁情报团队可以将外部报告转化为 AttackFlow 候选、规范实体和证据关系。系统先生成入库预览和质量检查，通过复核后再发布新知识版本，适合持续建设组织内部攻击模式库。

### 4.4 威胁猎捕与检测缺口分析

分析人员可以根据已命中攻击步骤查看可能缺失的前置或后续行为，并将其转化为待验证的日志、资产和检测线索。与仅按 IOC 搜索相比，这种基于行为过程的猎捕方式对基础设施轮换和样本变种更具适应性。

### 4.5 攻击组织研究与线索聚合

系统将规范攻击组织身份、厂商别名、关联名称、公开画像基线和本库报告观测分层管理。这既可以减少同一组织被拆成多个孤立节点，也避免将只能证明活动重叠的名称过度合并。

### 4.6 多客户安全运营与专家经验沉淀

对于 MSSP、大型集团或多业务单位安全团队，ARGUS 可将资深分析员复核过的攻击流和判断依据沉淀为可重复使用的组织资产，降低研判质量对个人经验的过度依赖。

## 5. 产品使用闭环

1. **综合查询**：输入 IOC、行为描述、工具、漏洞、攻击组织或报告线索。
2. **候选判定**：展示可能匹配的实体、历史报告和多条攻击流候选。
3. **路径研判**：在攻击主干上区分命中、补全和预测，查看分支、泳道和行为上下文。
4. **证据复核**：从节点、关系或组织声明回到原始来源片段。
5. **研判输出**：保存分析快照，并输出待验证信号、参考处置建议或复盘材料。
6. **知识入库**：新报告和新路径经质量门与复核后发布，进入下一次研判的知识基线。

## 6. 技术设计概述

### 6.1 数据设计

ARGUS 不将“图上能显示的任何内容”都定义为同一类节点，而是将数据拆分为四个主要层次：

- **来源证据层**：保存来源文档、文档哈希、发布者、时间和可定位证据片段；
- **规范知识层**：保存 IOC、恶意软件、工具、漏洞、组织等可跨来源复用的规范实体，同时保留原文提及和别名；
- **攻击活动层**：保存具体活动中的原子行为、过程依赖、分支和行为上下文关系；
- **分析投影层**：保存一次查询的命中、补全、预测、主干、泳道和候选排序，不将这些运行状态混入历史事实。

攻击流的主节点是“动词 + 对象”形式的原子行为，而不是报告标题、整句原文或 IOC。过程关系可表达明确先于、推进至、提供必要条件、直接触发、成功后进入和失败后进入等语义。

### 6.2 前端设计

前端采用查询优先的桌面 Web 信息架构，主要页面包括综合查询、IOC / 实体详情、AttackFlow 候选、攻击路径研判、情报图谱、历史报告、攻击组织画像、情报入库和路径复核。

攻击过程默认使用主干布局，将大量 IOC 折叠为可展开的上下文组；也支持按阶段、资产或行为类型呈现的泳道视图。全景图谱支持从局部邻域逐步展开，而不是首屏加载一张不可读的巨型关系网络。

前端展示依赖后端运行时 API，推荐案例可以精选，但候选匹配、图谱关系、组织数量、证据数量和高关联实体均由真实数据动态计算，不依赖前端伪造结果。

### 6.3 后端设计

当前后端使用 Python FastAPI 提供服务，SQLite 作为单机版唯一事实源。服务按业务边界分为两条链路：

- **在线研判链**：只读已发布知识，完成实体查询、攻击流匹配、补全、预测和分析快照生成，不直接修改历史图谱；
- **高保真入库链**：完成来源归档、抽取预览、实体消歧、质量门、候选复核、显式发布和知识版本回滚。

系统对 IP、域名、URL、哈希、CVE 和 ATT&CK 编号优先使用确定性规则规范化，而不将所有判断交给大模型。攻击组织和恶意软件等软实体使用别名、外部标识、上下文和阈值拒识进行消歧，模糊结果进入复核而不是自动合并。

### 6.4 数据抽取流程

数据抽取以“先形成局部事件图，再组装为可发布 AttackFlow”为原则，典型流程如下：

1. **来源归档**：保存原始文档身份、来源元数据、内容哈希和可定位文本；
2. **活动分段**：先判断报告中包含零个、一个还是多个独立攻击活动；
3. **分块抽取**：使用受 JSON Schema 约束的模型抽取原子行为、过程关系、行为上下文和原文 quote；
4. **规范化与消歧**：对强类型 IOC 进行确定性规范化，对组织、工具和恶意软件生成合并或待复核候选；
5. **活动图组装**：只在存在证据或强约束时连接局部行为，避免因共享组织、工具或时间而伪造因果边；
6. **主干与泳道投影**：从完整事实图中选择符合研判目标的主干，保留分支、关键上下文和泳道位置；
7. **质量门与局部返修**：检查节点原子性、边证据、主干连续性、跨活动错连和上下文身份，只对失败片段进行针对性返修；
8. **复核与发布**：候选经修订、接受或拒绝后，以独立知识版本发布并保留回滚能力。

报告中如果只有 IOC 或背景信息，系统允许输出“无攻击路径”的有效结果，同时保留其实体和证据，而不为了生成图而编造攻击步骤。

### 6.5 传统算法与大模型的分工

ARGUS 将大模型用于长文本理解、活动分段、局部行为抽取和解释性文本生成；将确定性规则和图算法用于 IOC 规范化、结构校验、证据对齐、路径连通性、候选排序、阈值拒识和版本管理。

这种分工的目的是充分利用模型的语义理解能力，同时将可以精确判断的问题从模型中剥离，减少幻觉、输出波动和不可复现性。

## 7. 技术架构与演进能力

当前版本采用 React / TypeScript 桌面 Web 前端、Python FastAPI 后端和 SQLite 数据库，优先保证单机部署、数据可复现、演示稳定和证据可追踪。模型服务通过 OpenAI-compatible 接口解耦，可根据成本、速度、准确率和私有化要求替换具体模型。

生产化阶段可将主数据库迁移至 PostgreSQL，并按需增加对象存储、向量检索、任务队列、权限控制和多租户隔离。图数据库应作为确有多跳查询瓶颈后的可选投影，而不在早期与主库双写，以控制系统复杂度。

## 8. 建设与应用收益

ARGUS 适合作为现有 SIEM、EDR、NDR、SOAR 和威胁情报平台之上的研判与知识组织层，而不是强行替换已有安全设备。其主要建设收益包括：

- 缩短从告警线索到形成调查思路的时间；
- 降低分析人员在多个工具和多份报告间手工拼接过程的成本；
- 提升研判结论的可解释性、复核效率和审计能力；
- 将资深分析员的经验沉淀为可检索、可继承的攻击模式资产；
- 为威胁猎捕、检测补强、应急复盘和组织画像提供统一数据基础；
- 在使用大模型提高信息处理效率的同时，通过证据、质量门和人工复核保留安全业务所需的可控性。

## 9. 产品边界

ARGUS 是研判和知识运营平台，不将候选路径、攻击组织归因或后续预测包装成确定事实，也不直接执行封禁、隔离或配置修改。平台输出的是带来源、状态、分数和验证方向的研判依据，最终处置仍由分析人员根据实际环境决定。

这一边界使 ARGUS 能够更安全地接入现有安全运营体系：它提高人的研判效率和知识利用率，但不越过证据和授权代替人作出高风险决策。
